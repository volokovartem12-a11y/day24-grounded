# День 24. Цитаты, источники и анти-галлюцинации

RAG из дня 23, доработанный так, что каждый ответ содержит **источники** и
**дословные цитаты**, а при слабом контексте ассистент говорит **«не знаю»**
и просит уточнить вопрос.

## Формат ответа

```
Ответ: Память разделена на три слоя: краткосрочную, рабочую и долговременную [1]…

Источники:
  [1] day11-memory-layers/README.md — … > Описание модели памяти  (day11-memory-layers/README.md#structure-002)

Цитаты:
  [1] «Долговременная (`LongTermMemory`) | профиль, решения, знания …»

Проверка: все цитаты (1) найдены во фрагментах дословно ✅
```

## Как обеспечена обязательность

```
вопрос ─► упомянут день, которого нет в базе? ─► «Не знаю» + список существующих дней
       ─► день не упомянут и лучшая близость < порога? ─► «Не знаю» + уточняющий вопрос
       ─► поиск (rewrite + фильтр + реранкер из дня 23)
       ─► модель возвращает JSON: ответ, номера фрагментов, дословные цитаты
       ─► проверка кодом ─► проблемы? ─► одна повторная попытка с перечнем замечаний
       ─► нет подтверждённых цитат? ─► «Не знаю: ответ не подтверждён цитатами»
```

| Требование | Как обеспечено |
|---|---|
| **Источники** | собираются **кодом** по номерам фрагментов: `source` + `section` + `chunk_id`. Модель не может выдумать путь к файлу. |
| **Цитаты** | каждая цитата сверяется с текстом своего фрагмента: должна встречаться **дословно** (с точностью до регистра, пробелов, вида кавычек и «ё»). Пропуск можно обозначить «…» — части ищутся по порядку. Короче 15 символов или без содержательного текста — отбрасывается. |
| **Обязательность** | нет JSON, нет цитат, выдуманные цитаты → модель получает перечень замечаний и одну повторную попытку. Не справилась — ответ **не выдаётся**, вместо него «не знаю». |

## Совпадает ли смысл ответа с цитатами

Две независимые проверки (`verify.py`):

1. **Ключевые элементы ответа есть в цитатах** — без модели. Числа, имена функций и
   файлов, идентификаторы, латинские термины из ответа должны найтись в цитатах
   («56,7%» в ответе = «56.7%» в цитате). Если в ответе их нет — сравниваются значимые
   слова, без служебной обвязки вроде «согласно базе».
2. **LLM-судья** — отдельный запрос: подтверждают ли цитаты каждое утверждение ответа →
   `supported` / `partial` / `unsupported` + список неподтверждённых утверждений.

Важно: «подтверждён цитатами» и «правильно отвечает на вопрос» — разные свойства.
Ответ может дословно опираться на цитату, но цитата будет не про то. Поэтому отдельно
считаются **обязательные факты** из контрольного набора.

## Режим «не знаю»

| Ситуация | Что происходит | Модель вызывается? |
|---|---|---|
| Упомянут день, которого нет в базе | «В базе нет проекта дня N. Есть дни: 9, 10, 11, …» | нет |
| День не упомянут, лучшая близость ниже порога | «Не знаю» + ближайшие темы базы как подсказка | нет |
| Фильтр отсёк все фрагменты | «Не знаю» + уточнение | нет |
| Модель не нашла ответа во фрагментах | её `clarification` | да |
| Ответ не подтверждён цитатами | «Не знаю: ответ не подтверждён» | да |

**Порог «не знаю» подбирается по данным** (`calibrate.py`): по лучшей близости каждого
вопроса он отделяет вопросы с ответом от вопросов без ответа. Главное условие — не
отказывать там, где ответ есть; порог ставится посередине зазора.

## Контрольные вопросы

**10 вопросов с ответом** (8 по проектам + 2 общих) — проверка источников, цитат и смысла.
**4 вопроса для режима «не знаю»**: 2 без ответа в базе (проект дня 18, рецепт борща)
и 2 расплывчатых («А сколько там было в итоге?», «Что там с сервером?»).

## Что выяснилось при проверке

- **Порог по близости хрупок.** На локальных эмбеддингах он чисто разделил контрольные
  вопросы (с ответом 0.140–0.249, без ответа 0.098–0.123), но чуть перефразированный
  вопрос про день 11 провалился под порог — ложное «не знаю». Причина: порог подобран
  на тех же формулировках, зазор узкий.
- **Исправление — фильтр по метаданным.** Если в вопросе упомянут существующий день,
  кандидаты ищутся внутри его файлов, а порог по близости к ним не применяется.
  Несуществующий день — сразу «не знаю». Порог по близости остался для вопросов без дня.
- **Цена этого решения:** вопрос «рецепт борща в проекте дня 11» теперь доходит до
  модели. Его ловит вторая линия защиты — без дословных цитат ответ не выдаётся.
- **Найдены и закрыты дыры проверки**: «цитата» из строки-разделителя `# -------`
  принималась — теперь требуется содержательный текст; служебные фразы ответа штрафовали
  честный ответ — теперь не учитываются.

## Файлы

| Файл | Роль |
|---|---|
| `grounded.py` | ответ с источниками и цитатами: проверка, повтор, режим «не знаю» |
| `verify.py` | совпадение смысла: ключевые элементы + LLM-судья |
| `calibrate.py` | пороги фильтра и «не знаю» → `config.json` |
| `retrieval.py` | поиск из дня 23 + фильтр по метаданным (день из вопроса) |
| `evaluate.py` | проверка на 14 вопросах → `output/grounded_eval_*.md` |
| `agent.py` | агент: ответы в формате выше, `/trace` |

## Запуск (PowerShell)

```powershell
cd "путь\до\day24-grounded"
Unblock-File .\run.ps1
.\run.ps1                                        # пороги + проверка на 14 вопросах
.\run.ps1 -Mode ask -Query "Какие слои памяти в дне 11?"
```

## Проверка ТЗ

| Пункт ТЗ | Где |
|---|---|
| Ответ | поле `answer` |
| Список источников (source + section/chunk_id) | собирается кодом, `grounded.py` |
| Цитаты из найденных чанков | дословная сверка, `quote_in_chunk()` |
| Есть ли источники в каждом ответе | метрика «из выданных ответов — с источниками» |
| Есть ли цитаты в каждом ответе | метрика «из выданных ответов — с цитатами» |
| Совпадает ли смысл ответа с цитатами | ключевые элементы + LLM-судья |
| Ниже порога релевантности — «не знаю» и уточнение | порог `answer_min` + метаданные + уточняющий вопрос |
